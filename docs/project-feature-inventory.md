## 1. 项目定位

**一句话**：一个**本地运行**的 A 股 ETF 交易指引与回测研究工作台——把"指数数据 → 指数/ETF 技术指标 → 策略信号 → 历史回测与有效性验证 → 每日操作建议"串成闭环，但**不连接券商、不自动下单**，产出的是人工执行的决策依据。

- 目标市场：中国大陆 A 股 ETF（含通过 A 股账户交易的港股/跨境 ETF），不含港股通直接标的。
- 使用方式：本机启动 Web 界面（NiceGUI 为主，Streamlit 为回退），或跑命令行研究脚本。
- 语言：所有面向用户的文案为中文。
- 数据只存本地（SQLite 元数据 + Parquet 行情），不上传云端。

## 2. 技术栈与运行形态

| 项目 | 内容 |
|---|---|
| 语言 | Python ≥ 3.11 |
| 包名 | `etf-trading-system`（`pip install -e ".[dev]"`） |
| 技术指标/数值 | pandas、numpy |
| 存储 | SQLite（元数据/状态/任务）、Parquet（行情与缓存，pyarrow） |
| 主 UI | NiceGUI ≥ 3.14（端口 8502），图表用 Apache ECharts |
| 回退 UI | Streamlit ≥ 1.36（端口 8501），图表用 streamlit-lightweight-charts + Altair |
| 数据源 | Tushare（主，需 Token）+ AkShare（备）；DuckDB 在依赖里但当前未使用 |
| 配置 | YAML（`configs/`） |
| 测试 | pytest，55 个测试文件；**当前全量 695 passed / 1 skipped** |
| 代码规模 | 90 个源码文件 + 55 个测试文件（约 2.8 万行 Python） |

**启动方式**

```
python scripts/run_nicegui.py            # 主界面 http://127.0.0.1:8502
python -m streamlit run app.py           # 回退界面 http://127.0.0.1:8501
python scripts/init_db.py                # 建/升级 SQLite 表结构
python scripts/update_data.py            # 补数据（初始化主表 + 补齐自选池历史）
python scripts/run_research.py --limit 20   # ETF 级候选策略研究
python scripts/run_index_research.py        # 指数趋势 V1 全量回测并发布证据包
```

**重要约束**：所有数据路径都是**相对路径**（`database/`、`data/parquet`、`reports/`、`configs/`），因此必须在仓库根目录下启动。

## 3. 领域核心概念（理解全项目的前提）

| 概念 | 含义 |
|---|---|
| **ETF 主列表 `etf_master`** | 全市场 ETF 名录（实测 1544 条），含代码、名称、分类、跟踪指数 |
| **自选/每日计算池 `user_etf_watchlist`** | 用户从中挑选出、要每天出建议的 ETF（**实测当前为空**） |
| **指数目录 `index_catalog`** | 项目关注并回测的指数清单（实测 210 条），带市场/分类/类型/池/基日证据 |
| **三类池 `pool`** | `core`（核心，可参与交易与统计）、`research`（研究用，不允许开新仓）、`reserve`（候补，默认对用户隐藏） |
| **官方基日 `baseline_source`** | 指数能否作为可交易基准的前提。只有 `official_api / official_methodology / official_factsheet` + 可解析日期才算"官方基日" |
| **数据源溯源 `data_source`** | 每行行情记录由哪个适配器产出（`tushare_*` / `akshare_*` / `sina` 等） |
| **指数↔ETF 映射 `index_etf_mapping`** | 每个指数对应的可交易 ETF（实测 800 条），用于"看指数、买 ETF"的落地 |
| **历史完整度 `completeness_status`** | 每指数本地历史相对其官方基日是否完整（`COMPLETE` / `INCOMPLETE` / `BASELINE_UNVERIFIED` / …） |

## 6. 一个典型请求会怎么流转

**日常出建议（今日行动 → 每日建议）**
1. 读取自选池 `user_etf_watchlist`
2. 逐只读取 `prices/<code>.parquet`，现算技术指标，取最后一行
3. **硬编码填充**：RS 排名 0.2、折溢价 0.0、数据质量 1.0、港股市开市 True、大盘风险开关 True
4. 调用 `TrendStrategy.evaluate` 得到 BUY/SELL/REDUCE/HOLD/FORBID
5. 渲染成中文 Markdown 日报（市场状态固定为"震荡"、风险偏好固定为"平衡偏保守"）

**指数趋势研究（策略实验室 → 指数趋势回测）**
1. 读 `configs/index_research.yaml`（逐字段与冻结锁定值比对）
2. 从 `indexes/*.parquet` 载入本地指数历史，按"官方基日 + 完整性 + OHLC 有限为正"准入，其余记入排除清单
3. 对每个指数跑策略与买入持有两条腿，覆盖全历史/逐年/阶段/5 年滚动/三档缓冲/双倍成本
4. 计算六道闸门 → 汇总状态
5. 暂存目录写 10 个产物 → 用与加载时**同一个**严格校验器校验 → 原子替换 → 换 `latest.json` 指针
6. 界面只读该证据包，不自动计算

## 11. 工程约定（供判断"改动是否符合项目习惯"）

- `src/etf_trading/` 存放业务代码，按域分包：`data` / `strategy` / `risk` / `backtest` / `research` / `universe` / `report` / `ui` / `nicegui_app`。
- `scripts/` 放可运行工作流，`configs/` 放 YAML，`tests/test_*.py` 放测试。
- `data/`、`database/`、`logs/`、`reports/` 是**生成的本地状态，不入库**（含 SQLite、行情、日志、报告、截图）。
- 风格：4 空格缩进、公开函数带类型标注、领域规则写简短 docstring、`snake_case` 函数与模块、`PascalCase` 类、优先 `pathlib.Path`。
- **参数放 `configs/` 而非硬编码**（当前有明显违例，见第 10 节第 3/4 条）。
- 测试要求：网络访问必须 mock；提交前跑全量 `pytest`（当前基线 695 passed / 1 skipped）。
- 每项实质性改动要在 `docs/task-memory.md` 记录"改了什么、用什么命令验证、下次要注意什么"。
- 项目采用较强的证据文化：结论必须可被独立重算复核，失败结论不得用措辞包装成成功。
