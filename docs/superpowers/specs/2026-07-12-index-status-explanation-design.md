# 指数数据状态说明设计

## 目标

把数据维护、市场参考和任务结果中的指数状态改为“缺什么、已到哪里、为什么不能用于交易”的用户语言，避免向普通投资者直接暴露难以理解的内部术语。

## 状态说明规则

| 内部状态 | 首要展示 | 辅助说明 |
| --- | --- | --- |
| `STALE` | `已更新至 YYYY-MM-DD，缺少 YYYY-MM-DD 行情` | 数据源最新可用日期与下一步“仅更新最新行情”提示。 |
| `INCOMPLETE` | `应从 YYYY-MM-DD 开始，当前仅有 YYYY-MM-DD 起的数据` | 保留当前完整性评估原因。 |
| `BASELINE_UNVERIFIED` | `已有 YYYY-MM-DD 至 YYYY-MM-DD 的行情，但缺少官方基日` | `暂时无法判断是否从指数起点完整，不作为交易依据。` |
| `MISSING_HISTORY` / `EMPTY` | `数据源未返回该指数的历史行情` | 显示指数代码和已尝试的数据源类型；若有错误则显示简短错误原因。 |
| `COMPLETE` | `历史从官方基日开始，数据完整` | 显示官方基日与本地覆盖区间。 |

## 展示边界

- 任务中心汇总继续统计“行情仍滞后”“历史不完整”等类别，但每行详情必须给出具体缺失日期或起始日期。
- 表格的“历史完整性说明”使用上述完整句子；不再单独以“基日待核验”作为主结论。
- 市场页和研究页沿用同一说明字段；研究池或未完成完整性核验的指数始终不提供新开仓或回测买入输入。
- 代码保留内部枚举值，用于筛选、持久化和测试；仅改变面向用户的显示模型与文案。

## 验收

- 对 2026-07-09 最新、目标 2026-07-10 的记录，页面显示“缺少 2026-07-10 行情”。
- 对有长历史但官方基日未知的记录，页面同时显示实际覆盖区间与“缺少官方基日”。
- 对空响应记录，页面不称为“历史不完整”，而明确为“数据源未返回”。
- NiceGUI 表格、任务中心、市场参考页均不把内部状态码作为主文案。
