# 页面配置 Tushare Token 设计

## 目标

在 NiceGUI 工作台右上角提供“数据源设置”入口。用户可填写并保存 Tushare Token；保存后，后续发起的数据请求立即以 Tushare 为主源。未填写 Token 时，系统继续以 AkShare 完成请求，并清晰说明 Tushare 未配置。

## 存储与安全边界

- Token 保存到现有本地 SQLite 数据库的单行运行时设置表；这是用户明确选择的明文存储方案。
- 页面只显示脱敏状态，不回显完整 Token。
- Token 不进入 YAML、源码、日志、任务结果、市场数据或 Git。
- 用户应保护本机数据库文件；任何能读取数据库的本机账户都可能读取该 Token。

## 组件与数据流

1. `SQLiteStore` 增加运行时设置读写接口，并在初始化时创建设置表。
2. provider factory 接受可选的运行时 Token；未提供时保持环境变量优先、再读取本地设置、最后为空的顺序。
3. NiceGUI 顶栏增加数据源状态按钮与设置弹窗。保存后刷新状态；不需要重启服务器。
4. 现有页面和后台任务在创建 provider 时读取同一运行时设置，因此保存后的新请求自动切换到 Tushare 优先。
5. Token 缺失导致的 Tushare 配置错误继续走现有显式 AkShare 回退，并保留“未配置”原因。

## 交互

- 已配置：按钮显示 “Tushare 已配置”。
- 未配置：按钮显示 “Tushare 未配置（使用 AkShare）”。
- 弹窗提供 Token 输入、保存、清除三个操作；保存成功后只显示掩码，清除后立即恢复回退模式。

## 验证

- 存储测试验证保存、读取、清除和 Token 不出现在状态文本中。
- factory 测试验证运行时 Token 优先于环境配置。
- 顶栏测试验证已配置/未配置标签及设置入口。
- 运行全量离线测试；真实 Tushare 冒烟测试继续必须显式开启。
