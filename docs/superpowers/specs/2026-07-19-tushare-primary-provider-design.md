# Tushare 主数据源与显式 AkShare 回退设计

日期：2026-07-19

## 背景

系统已经通过 `DataProvider` 隔离数据源，但 NiceGUI、Streamlit、后台维护任务和脚本仍直接创建 `AkShareProvider`。这使 `configs/data_sources.yaml` 中的 `default_provider` 没有真正控制运行时数据源，也无法统一报告数据源切换。

本次接入使用 Tushare Python SDK，并将 SDK 的 HTTP 地址指向已授权的代理服务。账号 Token 只从运行环境读取，不写入源码、YAML、测试数据、日志或 Git 历史。

## 目标

- Tushare 是 ETF 和指数维护流程的首选数据源。
- Tushare 请求失败、返回无效数据或不支持目标品种时，先生成用户可见的明确告警，再使用 AkShare。
- 备用源成功时任务继续完成，但状态必须显示“完成，但使用了备用源”。
- 两个数据源都失败时才把任务判定为失败，并同时提供经过脱敏的错误原因。
- 所有返回及落盘行情保留真实数据来源，不能把 AkShare 数据标记为 Tushare。
- 现有策略、存储、回测和 UI 继续依赖标准化的 `DataProvider` 契约。

## 非目标

- 不接入 MCP 作为应用运行时数据通道；当前项目是 Python 应用，SDK 更适合现有 provider 边界。
- 不引入盘中高频或分钟行情工作流。
- 不扩展新的交易策略、指标或投资结论。
- 不在本次工作中重构与数据源选择无关的 UI 或存储代码。

## 总体架构

新增三个组件：

1. `TushareProvider`
   - 实现现有 `DataProvider`。
   - 封装 SDK 初始化、代理地址、限流、重试、代码解析和字段标准化。
   - 不负责 UI 展示或数据库持久化。
2. `PrimaryFallbackProvider`
   - 以 `TushareProvider` 为主源、`AkShareProvider` 为备用源。
   - 在每个 provider 方法边界执行主源调用、响应校验、告警收集和备用调用。
   - 暴露本次操作产生的结构化 `ProviderNotice`，供调用方一次性读取并清空。
3. `create_data_provider()`
   - 从配置和环境变量创建组合 provider。
   - 替换应用、维护任务和脚本中的直接 `AkShareProvider()` 构造。

调用链如下：

```text
业务服务
  -> PrimaryFallbackProvider
     -> TushareProvider
        -> 成功且通过接口级校验：返回标准化数据
        -> 失败/无效/不支持：记录 ProviderNotice
     -> AkShareProvider
        -> 成功：返回备用数据并保留告警
        -> 失败：抛出包含双方脱敏原因的组合异常
```

## 配置与密钥

运行时配置约定：

- `TUSHARE_TOKEN`：Tushare Token。缺失时主源被视为配置不可用，生成告警并使用 AkShare。
- `TUSHARE_API_URL`：代理 API 地址；未设置时使用项目配置的代理地址。
- `configs/data_sources.yaml`：保存 `primary_provider: tushare`、`fallback_provider: akshare`、代理地址、重试次数和每分钟请求上限，不保存 Token。
- 默认请求上限低于账号标称的 150 次/分钟，为并发和重试留出余量。

异常、日志、任务结果和测试断言必须通过统一的脱敏函数过滤 Token、包含 Token 的 URL 和常见鉴权头格式。

## Provider 方法与数据口径

### ETF 主数据

`fetch_etf_list()` 使用 `fund_basic(market="E", status="L")`：

- 根据 Tushare 的基金类型字段和名称严格筛选 ETF，排除 LOF、封闭式基金等其他场内基金。
- 将 `ts_code` 拆为六位 `etf_code` 和 `exchange`。
- 映射名称、管理人、上市日期、存续状态等现有主表字段。
- Tushare 基础列表没有的实时价格、成交量和成交额保持空值，不使用占位数字。
- 分类继续使用现有 `classify_etf`，避免数据源切换改变业务分类规则。

`fetch_exchange_traded_etf_spot()` 优先使用能满足现有字段要求的 Tushare 接口。若代理权限或接口不能提供必要的实时字段，则记录“接口不支持/权限不足”的告警并使用 AkShare 现货列表。基础信息请求成功不等于实时行情请求成功，两者分别记录来源。

### ETF 日线与复权

`fetch_etf_daily()` 使用 `fund_daily` 获取原始行情：

- 将交易日期转为 `datetime64`，结果按日期升序并去重。
- 映射 OHLC、成交量、成交额和涨跌幅；Tushare 的成交额从千元换算为项目使用的元。
- ETF 代码根据交易所转换为 Tushare 后缀代码。
- `adjust="none"` 返回未复权行情。
- `adjust="qfq"` 时同时获取 `fund_adj`，按最新有效复权因子归一化价格；没有覆盖完整日期区间的复权因子视为无效响应。
- 请求 `qfq` 但 `fund_adj` 无权限、为空或结构无效时，不得返回未复权数据冒充前复权数据；必须告警并由 AkShare 完成整个日线请求。

### ETF 净值

`fetch_etf_nav()` 使用 `fund_nav`，映射净值日期、单位净值、累计净值等可用字段。接口没有 IOPV 或溢价率时保持空值。目标基金在请求区间确实没有净值记录时可以返回标准空表；鉴权错误、无效结构和异常响应不能伪装成空结果。

### 指数日线

`fetch_index_daily()` 使用 `index_daily`：

- 指数目录增加独立的可选 Tushare 代码映射，不能复用只为 AkShare 设计的 `provider_symbol`。
- 优先使用配置中的明确映射；缺失时可通过 `index_basic` 做精确解析和进程内缓存。
- 代码存在歧义或无法精确解析时不采用前缀猜测，记录告警并回退 AkShare。
- Tushare `index_daily` 明确不覆盖的申万行业指数，以及当前接口不覆盖的港股指数，按“已知能力缺口”记录并使用 AkShare，而不是伪装成临时网络故障。
- 输出保持现有 `index_code`、交易日期、OHLC、成交量、成交额和 `data_source` 契约。

### 交易日历

`fetch_trade_calendar()` 使用 `trade_cal`，映射交易所、日历日期和开市标记。主源失败后回退到 AkShare provider 的现有工作日实现，并明确提示备用结果只是工作日近似值，不能将其描述为官方交易日历。

## 响应校验与空数据语义

每个接口定义自己的必需列和非空规则：

- ETF 主数据必须包含至少一条有效 ETF 记录。
- 日线结果必须包含代码、日期和完整 OHLC；存在重复日期、不可解析日期或全空价格时视为无效。
- 历史请求的空结果只有在区间不含预期交易日、资产尚未上市或明确无记录时才是合法空数据。
- 不能仅因周末、节假日或停牌返回空结果就产生错误告警。
- 响应中的业务错误码、权限消息和 SDK 异常统一转换为 provider 异常类别。

## 重试、限流与失败分类

Tushare provider 使用进程内限流器和有限重试：

- 网络超时、连接中断和服务端临时错误可以重试，并采用有上限的退避。
- 鉴权失败、明确权限不足、参数错误和接口不支持不重复消耗额度，直接进入告警与回退。
- 限流错误按服务端提示或本地退避策略重试；超过重试上限后回退。
- 批量任务中的每次 SDK 调用都经过同一个限流器，包括复权因子和代码解析请求。

`ProviderNotice` 至少包含操作、资产代码、失败类别、脱敏原因、备用数据源、时间戳和是否属于已知能力缺口。

## 用户可见状态

### NiceGUI 与 Streamlit

- 单项任务回退成功后显示黄色告警，说明目标、Tushare 原因和本次实际使用的备用源。
- 批量任务合并同类告警，显示回退总数、部分示例代码和可展开的完整列表，避免每只 ETF 连续弹窗。
- UI 不显示 Token、带 Token 的代理 URL、堆栈或 SDK 内部对象。

### 持久化维护任务

- 扩展维护任务展示语义，支持“完成，但有警告”。
- 备用成功时结果数据照常保存，同时把告警摘要写入维护任务记录；刷新页面后仍可恢复该状态。
- 任务状态不能因备用成功显示为纯成功，也不能因已成功落盘显示为失败。
- 两个数据源都失败时保持现有失败语义，持久保存双方脱敏原因。

### 命令行

- 备用成功时向标准错误输出告警，主流程正常退出。
- 双源失败时返回失败退出码。
- 批量脚本在结尾打印回退汇总。

## 数据来源与落盘

- Tushare 行情使用细分来源值，如 `tushare_fund_daily`、`tushare_index_daily`。
- AkShare 继续使用现有细分来源值；补齐当前未明确设置来源的分支。
- 数据合并仍按资产代码和交易日去重，以较新的请求结果覆盖同日旧记录。
- 同一 Parquet 可以包含不同时段、不同 provider 的记录；每行来源必须反映该行实际取得数据的接口。
- 告警属于操作元数据，不作为行情列写入 Parquet。

## 测试策略

### 单元测试

- 使用模拟 Tushare SDK 测试 ETF 列表筛选、字段映射、交易所后缀、日期排序和单位转换。
- 验证前复权公式、复权因子缺失和跨日期对齐。
- 验证指数明确映射、精确解析缓存、歧义代码和已知不支持路由。
- 验证交易日历字段和空数据语义。
- 验证重试、限流、告警分类、告警聚合和 Token 脱敏。

### 组合与 UI 测试

- Tushare 成功时不能调用 AkShare。
- Tushare 失败且 AkShare 成功时返回备用数据，并生成一次可读取的结构化告警。
- 两个数据源都失败时组合异常包含双方来源但不包含密钥。
- 持久化任务在页面重载后仍显示“完成，但有警告”。
- 批量任务只显示聚合告警，不为每个资产单独通知。
- 现有 provider、存储、研究、回测和两个 UI 的回归测试继续通过。

### 真实代理冒烟测试

真实测试必须显式启用并从环境读取 Token，默认 pytest 不访问网络。测试范围：

1. 拉取场内基金列表并确认包含有效 ETF。
2. 拉取一只 ETF 的短区间日线并验证日期、OHLC 和来源。
3. 拉取一个沪深指数的短区间日线。
4. 拉取一个短区间交易日历。
5. 在权限允许时验证前复权；权限不足时验证告警和 AkShare 回退。

真实测试输出只能报告接口、行数、日期范围、来源和状态，不能打印 SDK 配置或完整响应对象中的敏感信息。

## 实施范围

预计改动集中在：

- 新增 Tushare provider、组合 provider、配置加载和 provider factory。
- 更新依赖和数据源配置。
- 替换 NiceGUI、Streamlit、维护 runner 和脚本的直接 AkShare 构造。
- 扩展维护任务及同步任务的警告展示。
- 增加 provider、factory、任务状态和真实冒烟测试。
- 更新 README 的本地环境变量和验证说明。
- 在完成后更新 `docs/task-memory.md`。

不改变策略计算公式、SQLite 行情主表结构、既有 Parquet 文件布局或页面信息架构。

## 验收标准

- 配置有效时，核心 ETF/指数请求首先调用 Tushare。
- 主源失败时用户能看见明确原因和 AkShare 回退事实。
- 备用成功的数据正常落盘，并带真实 `data_source`。
- 页面刷新后仍能看到持久化任务的回退警告。
- 缺少 Token 时系统仍可通过 AkShare 工作，但不能静默运行。
- `qfq` 请求永远不会收到伪装成前复权的未复权 Tushare 数据。
- 日常批量调用受限流器约束，不超过配置上限。
- 默认测试不访问真实服务；显式冒烟测试可使用代理权限通过，或按设计验证权限不足后的回退。
- 完整测试套件通过，且任何输出和 Git diff 中都不包含 Token。
