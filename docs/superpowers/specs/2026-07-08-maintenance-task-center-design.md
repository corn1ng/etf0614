# 数据维护任务中心设计

日期：2026-07-08
项目：`etf0614`

## 1. 背景

当前 `数据维护 -> 补齐任务` 页面已经把补齐动作放到 `run.io_bound` 中执行，并在任务开始时禁用按钮、弹出通知、写入一行“正在执行”。任务完成后也会展示结果表。

实际使用时仍然不清楚任务是否在运行或是否成功。主要原因是：

- 结果区是整个 `补齐任务` 页共享的，不在用户点击的按钮附近。
- 通知会自动消失，无法作为可靠的任务状态记录。
- 任务完成后的成功、失败、取消信息缺少统一位置，用户需要自己判断最新表格属于哪个任务。

本次设计引入页面内任务中心，让用户点击任意补齐按钮后，都能在同一个固定位置看到最新任务状态、时间和结果。

## 2. 目标

完成后，用户应能：

- 点击任意补齐按钮后，立即在任务中心看到任务已开始。
- 任务运行时看到明确的 `运行中` 状态和任务名称。
- 任务完成后看到 `成功`、`失败` 或 `取消` 状态。
- 在成功时看到摘要和结果表。
- 在失败时看到失败原因。
- 在连续执行多个任务时，清楚知道任务中心显示的是最近一次任务。

## 3. 非目标

本次不做：

- 真正后台队列或跨页面持久任务。
- 多任务并发管理。
- 每个指数或 ETF 的逐项真实进度，例如 `3/12 正在拉取 000300`。
- 任务取消按钮。
- 数据库里的任务日志结构调整。
- AkShare、Parquet、SQLite 或补齐服务的业务逻辑调整。

## 4. 信息架构

`数据维护 -> 补齐任务` 页面调整为：

```text
任务中心
主列表
ETF历史
指数历史
批量任务
说明文字
本页 UI 修正点
```

任务中心放在补齐任务内容区顶部。它不是浮层，也不遮挡页面；它是一个稳定的页面面板，用户滚动到补齐任务页后第一眼即可看到。

## 5. 任务中心内容

任务中心包含：

- 标题：`任务中心`
- 状态徽标：`空闲`、`运行中`、`成功`、`失败`、`取消`
- 任务名称：例如 `补齐全部指数历史`
- 运行时间：开始时间；完成、失败或取消时显示结束时间
- 摘要消息：例如 `正在执行，请稍候...`、`已检查 12 个指数`
- 结果明细：成功时展示现有结果表；失败或取消时展示现有空状态样式和原因

初始没有任务时，任务中心显示：

```text
暂无任务
点击下方补齐按钮后，这里会显示运行状态和最近结果。
```

## 6. 状态模型

新增页面内轻量状态对象：

```text
MaintenanceTaskStatus
- title: str
- state: idle | running | success | failed | cancelled
- message: str
- started_at: datetime | None
- finished_at: datetime | None
- result: object | None
- error: str
```

该对象只用于当前页面渲染期间的 UI 状态，不持久化到数据库。

状态转换规则：

```text
idle -> running
running -> success
running -> failed
running -> cancelled
```

当用户点击另一个任务时，任务中心替换为新任务的 `running` 状态。按钮禁用逻辑继续由 `_run_task` 控制。

## 7. 交互规则

- 任意补齐按钮点击后，任务中心立即更新为 `运行中`，并显示任务名和开始时间。
- 在进入 `run.io_bound` 前，任务中心必须已经渲染并 `update()`。
- 任务运行时，当前按钮禁用并保留现有 `ui.notify` 信息。
- 成功时，任务中心显示 `成功`、摘要消息和结果表，并刷新平台快照缓存。
- 失败时，任务中心显示 `失败` 和异常消息。
- `run.io_bound` 返回 `None` 时，任务中心显示 `取消`。
- `finally` 中按钮恢复可用。
- 任务中心始终显示最近一次任务，不保留历史列表。

## 8. 视觉设计

任务中心使用现有工作台视觉语言：

- 面板圆角不超过 8px。
- 使用轻量边框和白底，贴合 `workbench-task-panel`、`workbench-alert` 风格。
- 状态色沿用现有 CSS 变量：蓝色表示运行中，绿色表示成功，红色表示失败，黄色表示取消或警告。
- 内容密度保持紧凑，适合工具型工作台，不做大面积装饰。

建议新增 CSS：

```text
.workbench-task-center
.workbench-task-center-header
.workbench-task-center-status
.workbench-task-center-meta
.workbench-task-center-result
```

## 9. 代码边界

保持现有分层：

- `nicegui_app.pages.maintenance`
  增加任务状态对象、任务中心渲染函数，并让 `_run_task` 更新任务中心。
- `nicegui_app.theme`
  增加任务中心样式。
- `nicegui_app.components.tables`
  继续负责结果表渲染，不加入任务中心业务逻辑。
- `data.initialization`
  不改补齐服务和结果结构。

## 10. 测试要求

至少覆盖：

- `_run_task` 进入 `io_bound` 前已经更新任务中心为 `运行中`。
- 成功时任务中心显示 `成功`、成功摘要和结果表。
- 失败时任务中心显示 `失败` 和异常消息。
- `None` 结果时任务中心显示 `取消`。
- 按钮在任务开始禁用、结束后恢复可用。
- 现有通知和结果表渲染路径不回退。

## 11. 验收标准

满足以下条件即完成：

1. `数据维护 -> 补齐任务` 顶部出现任务中心。
2. 点击 `拉取并保存指数历史` 或 `一键初始化/补齐全部指数` 后，任务中心立即显示运行中。
3. 任务完成后，任务中心明确显示成功、失败或取消。
4. 成功时能看到摘要和结果表，失败时能看到错误原因。
5. 任务按钮仍会在运行期间禁用，结束后恢复。
6. 不改变补齐数据的业务逻辑和数据库结构。
