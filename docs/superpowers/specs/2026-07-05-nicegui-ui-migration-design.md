# NiceGUI UI 层迁移设计

日期：2026-07-05

## 背景

当前工作台的后端数据链路已经能支撑 ETF 主数据、历史行情、指数状态、每日计算池和策略实验室等流程，但 Streamlit 原生控件在这个项目里暴露出明显的 UI 上限：

- 控件默认高度、间距和标题层级偏大，页面首屏被标题、说明、标签和选择器挤占。
- `市场地图`、`ETF数据` 这类高频工作页需要密集查看表格和图表，但 Streamlit 页面对数据的呈现仍然像长文档。
- 即使继续压缩 CSS，表单、tab、selectbox、expander 和 dataframe 的整体手感仍难做到桌面工作台式的紧凑。

本轮迁移的判断是：不继续在 Streamlit 原生控件上做大修补，改用 NiceGUI 重建 UI 层。NiceGUI 仍然是 Python 驱动的浏览器 UI 框架，当前 PyPI 最新版本为 `3.14.0`，支持 `Python >=3.10, <4`，与项目的 `Python >=3.11` 约束兼容。

## 目标

把主界面迁移到 NiceGUI，让工作台变成更像本地业务系统的密集操作界面，而不是 Streamlit 文档式页面。

具体目标：

1. 后端业务逻辑、数据结构、策略计算和数据源不做功能性改动。
2. 新 UI 复用现有 `SQLiteStore`、`ParquetStore`、初始化服务、数据覆盖统计、ETF/指数视图模型和图表 payload。
3. 建立稳定的 NiceGUI 应用外壳：左侧导航、顶部状态条、二级视图切换、紧凑表格、图表区和操作按钮。
4. 优先迁移每日高频页面：`今日行动`、`市场地图`、`ETF数据`、`数据维护`。
5. 保留 Streamlit 入口作为过渡回退，直到 NiceGUI 版本完成验收。
6. 迁移时同步审视当前 UI 的信息架构、层级、密度、视觉节奏和操作路径，做成更有质感、更符合审美、使用更顺手的专业工作台。

## 非目标

- 不重写 ETF 主数据、指数数据、行情补齐、策略回测或 AkShare provider。
- 不改变数据库 schema、Parquet 文件布局或已有计算结果含义。
- 不在第一版引入账户交易、自动下单、实时行情推送或多用户权限。
- 不追求营销页、仪表盘大屏或装饰型视觉效果。
- 不为了“酷炫”牺牲数据可读性、操作效率或风险提示清晰度。
- 不立刻删除 Streamlit UI；NiceGUI 验收后再决定清理节奏。

## 技术依据

NiceGUI 适合本项目的原因：

- UI 逻辑仍写在 Python 里，迁移成本低于 React/Vue 前后端分离。
- 底层是 FastAPI、Vue、Quasar 和 WebSocket 通信，控件和布局比 Streamlit 更接近常规 Web 应用。
- 支持表格、按钮、选择器、菜单、HTML、Markdown、图表嵌入、定时刷新和自定义 CSS。
- 状态更新是事件驱动，不依赖 Streamlit 的整页 rerun 模型，更适合高频筛选和局部刷新。

实现时在 `pyproject.toml` 增加：

```toml
"nicegui>=3.14.0",
```

Streamlit 依赖暂时保留，避免迁移期失去可用入口。

## 架构设计

新增一个独立 NiceGUI UI 包，不在现有 Streamlit `src/etf_trading/ui/` 里继续堆叠：

```text
src/etf_trading/nicegui_app/
  __init__.py
  main.py              # NiceGUI app factory 和 ui.run 入口
  state.py             # store、parquet_store、platform_status、刷新状态
  layout.py            # 应用外壳、左侧导航、顶部状态条、页面容器
  theme.py             # 全局 CSS、颜色、密度、表格/控件尺寸
  view_models.py       # UI 无关的数据整形，供 NiceGUI 页面复用
  components/
    __init__.py
    alerts.py          # 紧凑提示、错误、空状态
    controls.py        # 紧凑选择器、分段按钮、工具栏
    tables.py          # 通用表格配置和格式化
    charts.py          # lightweight chart payload 嵌入或降级图表
    status.py          # 顶部状态条和数据健康摘要
  pages/
    __init__.py
    action.py          # 今日行动
    market.py          # 市场地图
    etf_data.py        # ETF数据
    maintenance.py     # 数据维护
    research.py        # 策略实验室最小迁移
scripts/
  run_nicegui.py       # 本地启动脚本
```

`src/etf_trading/nicegui_app/` 是新 UI 层，职责只包含页面组合、状态管理和展示组件。业务计算继续留在现有 `src/etf_trading/` 数据、策略和研究模块里。

## 数据复用

第一版迁移应优先复用这些现有能力：

- `SQLiteStore`：ETF 主列表、每日计算池、配置状态。
- `ParquetStore`：ETF 和指数历史行情。
- `InitializationService`：初始化和补齐任务。
- `build_etf_data_overview(...)`：ETF 总览。
- `build_data_gap_detail(...)`、`build_data_coverage_summary(...)`：数据维护摘要。
- `build_index_etf_universe(...)`：指数到 ETF 样本池映射。
- `build_lightweight_chart_payload(...)`：K 线图 payload。
- `add_technical_features(...)`、`TrendRegimeClassifier`：指数趋势和买卖参考。

如果现有函数被 Streamlit 渲染代码绑定得太紧，迁移时只抽取 UI 无关的 view-model builder，不改底层计算语义。例如：

```text
Streamlit render 函数
  -> 提取数据准备逻辑到 view_models.py
  -> Streamlit 和 NiceGUI 分别消费同一份 DataFrame/dict payload
```

## 页面范围

### 今日行动

定位：每天打开后先看系统是否可用、今日计算池是否完整、下一步要做什么。

首屏内容：

- 顶部紧凑状态条：ETF 数、计算池数、指数历史覆盖、ETF 历史覆盖、最近更新时间。
- 当前行动摘要：可参与指数数量、需要补齐的数据、今日候选 ETF 数。
- 计算池表格：默认展示核心字段，行高约 30-34px。
- 明确的维护入口按钮：补齐历史、初始化主数据、刷新状态。

### 市场地图

定位：只观察指数和市场参与状态，不承载 ETF 行情下钻。

二级视图：

- `市场总览`：指数覆盖、强弱分类、风险提示、分类摘要。
- `指数买卖参考`：指数筛选、趋势状态、BUY/SELL 参考、触发条件。
- `指数K线`：指数选择、K 线图、均线/成交量/区间控制。

页面布局要求：

- 筛选器和当前指数状态在同一条工具栏或两行以内完成。
- K 线图必须尽量进入桌面首屏，不再被大标题和松散控件挤到下方。
- 指数页面不出现 ETF 行情入口，避免和 `ETF数据` 混淆。

### ETF数据

定位：ETF 资产层，回答系统里有哪些 ETF、哪些可交易、如何加入计算池、如何查看 ETF 行情。

二级视图：

- `ETF总览`：主数据、分类、交易所、跟踪指数、计算池状态、历史覆盖。
- `ETF行情`：ETF K 线图和历史行情状态。
- `搜索加入`：搜索 ETF、加入每日计算池。
- `每日计算池`：计算池明细、覆盖状态、移除或刷新。
- `指数样本池`：指数到 ETF 的候选映射，只表达交易载体归属，不承担市场判断。

页面布局要求：

- 搜索、筛选和主表格紧密排列。
- 大表格默认横向滚动或固定关键列，避免整页被宽字段撑乱。
- `指数样本池` 的文案使用“样本归属”“交易载体”“映射关系”，不写成指数分析页。

### 数据维护

定位：处理缺数据、初始化、补历史和查看任务结果。

二级视图：

- `数据健康`：覆盖摘要、缺口数量、最近同步时间。
- `补齐任务`：ETF/指数历史补齐、初始化主数据、修复缺口。
- `任务日志`：最近任务结果、错误信息、耗时。
- `设置`：只保留必要参数，避免低频设置占据首屏。

行为约束：

- 耗时任务必须由用户点击触发，不自动执行。
- 任务按钮要有明确 loading/disabled 状态。
- 失败信息用紧凑 alert 展示，并保留可复制的错误摘要。

### 策略实验室

定位：第一版只做最小可用迁移，避免拖慢高频页面落地。

范围：

- 展示研究任务状态和已有结果入口。
- 保留核心表格或结果摘要。
- 复杂回测参数表单、图表对比和复盘细节可以后续二期迁移。

## 当前 UI 审计要求

NiceGUI 迁移不是照搬 Streamlit 页面。实现前需要逐页审计当前 UI 中不合理的地方，并在新界面里主动修正。

重点审计项：

- 信息层级：是否存在标题、说明、子标题重复堆叠，导致真正的数据下沉。
- 页面密度：表格、筛选器、图表和提示之间是否有过多空白。
- 操作路径：高频任务是否需要多次滚动、多次切换或先读长说明才能执行。
- 板块边界：`市场地图`、`ETF数据`、`策略实验室`、`数据维护` 是否各自回答清晰问题。
- 数据呈现：表格列是否过宽、状态是否需要扫很多文字、关键数字是否缺少对齐和视觉权重。
- 反馈状态：刷新、补齐、错误、空数据、运行中是否明确但不喧宾夺主。
- 首屏价值：每个高频页面打开后，首屏是否能立刻看到“当前状态 + 下一步动作 + 核心数据”。

每迁移一个页面，都应先写出该页旧 UI 的 2-4 个主要问题，再对应落到新布局里修正。

## 视觉与交互设计

整体风格是“专业量化工作台”：安静、紧凑、有技术质感，第一眼比当前 Streamlit 版本更利落、更现代，但仍然以数据可读性为中心。

- 左侧导航宽度约 176-192px，导航项 36-40px 高。
- 顶部状态条 36-44px 高，显示关键数据状态和刷新按钮。
- 主内容区顶部不放大 hero，不使用大面积卡片堆叠。
- 二级视图使用紧凑 segmented control 或 tab，靠近页面标题。
- 工具栏控件高度约 32-36px，标签短、对齐稳定。
- 表格行高约 30-34px，数字列右对齐，状态列用短标签或小色块。
- 只用少量红、绿、蓝、灰表达状态，不做单一色系大面积铺满。
- 卡片仅用于少量状态摘要或重复项目，不能出现卡片套卡片。
- 页面主目标是让图表、表格和操作在首屏更早出现。

视觉方向：

- 使用偏金融终端的深浅混合界面：侧栏和顶部可以更沉稳，主内容保持清爽，避免整页灰白松散。
- 首页和高频页可以有少量“状态驾驶舱”质感，例如紧凑指标条、状态灯、趋势小图、分层工具栏。
- 图表区要成为页面视觉重心，K 线、均线、成交量和信号标记形成第一眼的专业感。
- 关键状态使用克制但明确的色彩：红色用于风险或下跌，绿色用于修复/通过/上涨，蓝色用于信息和选中态，琥珀色用于待处理。
- 控件要像工具台，不像表单问卷：同类操作集中成 toolbar，筛选、刷新、区间、显示项靠近图表或表格。
- 保留适度细节，例如 hover 高亮、选中行、紧凑状态徽标、固定表头、数字格式化和空状态插图式图标，但不做分散注意力的动画。
- 页面应该有“眼前一亮”的完成度：统一间距、统一圆角、统一字体尺度、统一状态色、统一表格密度，而不是只把 Streamlit 控件换成 NiceGUI 控件。

可用性底线：

- 不能用大面积装饰背景压低表格和图表对比度。
- 不能让关键按钮藏在图标里没有 tooltip 或文案。
- 不能因为动画、阴影或渐变导致页面显得像展示大屏而不是工作台。
- 不能让移动端或窄屏出现文字重叠、按钮挤压、表格不可滚动。

## 图表方案

优先路线：

1. 继续复用现有 `build_lightweight_chart_payload(...)`。
2. NiceGUI 页面用 `ui.html` 或封装组件加载 lightweight-charts，并把 payload 注入前端脚本。
3. 图表容器固定高度，桌面默认约 420-520px，窄屏自适应。

降级路线：

- 如果 lightweight-charts 嵌入第一版耗时过高，先用紧凑表格加简单折线图占位，但 `ETF行情` 和 `指数K线` 必须保留可用的历史数据查看能力。
- 降级只允许作为短期过渡，验收前仍应恢复 K 线图。

## 状态与错误处理

NiceGUI 没有 Streamlit 的自动 rerun 心智，状态需要显式管理：

- `state.py` 持有 store、parquet_store、platform_status 和最近刷新时间。
- 页面切换不重新执行耗时初始化。
- `刷新` 按钮只刷新当前页面所需的数据。
- 可选定时刷新只用于轻量状态摘要，不自动跑补齐任务。
- 所有耗时任务显示 loading、禁用重复点击，并在结束后局部刷新相关区域。
- 空状态给出下一步入口，例如去 `数据维护 -> 补齐任务`。

## 测试与验收

自动化测试：

- `tests/test_nicegui_navigation.py`：验证一级导航和二级视图配置。
- `tests/test_nicegui_view_models.py`：验证 UI 无关 view-model 的字段、空数据和排序。
- `tests/test_nicegui_app_import.py`：验证 NiceGUI app factory 可导入，不在 import 时启动服务器。
- 保留现有 Streamlit 和后端测试，确保迁移不破坏旧入口。

手动验收：

- 启动 NiceGUI：`python scripts/run_nicegui.py`。
- 桌面宽屏下，`市场地图 -> 指数K线` 的图表进入首屏或接近首屏。
- `ETF数据` 的主表格、搜索和筛选明显比 Streamlit 版本紧凑。
- `数据维护` 的补齐入口清晰，但不会自动执行耗时任务。
- 左侧导航、顶部状态条、二级视图切换在高频页面保持一致。

## 实施顺序

1. 审计当前 Streamlit 高频页面，记录每页 2-4 个主要 UI 问题和对应修正方向。
2. 增加 NiceGUI 依赖和 `scripts/run_nicegui.py`，建立新包骨架。
3. 抽取 UI 无关 view-model builder，先覆盖市场、ETF 数据和维护页所需数据。
4. 建立全局 shell、主题 CSS、左侧导航、顶部状态条和页面路由。
5. 先完成一版统一视觉语言：颜色、字体尺度、表格密度、按钮形态、状态徽标、图表容器。
6. 迁移 `市场地图`：先做 `市场总览`、`指数买卖参考`，再接入 `指数K线`。
7. 迁移 `ETF数据`：先做 `ETF总览` 和 `每日计算池`，再做 `ETF行情`、`搜索加入`、`指数样本池`。
8. 迁移 `数据维护`：健康摘要、补齐任务、任务日志。
9. 迁移 `今日行动`：状态摘要、行动入口、计算池表格。
10. 给 `策略实验室` 做最小可用入口，复杂研究页面留到后续计划。
11. 运行单元测试、本地浏览器截图验收和视觉走查，保留 Streamlit 回退入口。

## 验收标准

- 新增 NiceGUI 启动入口可用，且不会影响原 Streamlit 启动。
- NiceGUI 版本能打开 `今日行动`、`市场地图`、`ETF数据`、`数据维护` 四个高频页面。
- `市场地图` 与 `ETF数据` 的职责边界延续上一轮设计：前者看指数和市场，后者看 ETF 资产和行情。
- 高频页面明显更紧凑：标题、说明、控件和表格之间不再出现大面积空白。
- 高频页面相比当前 Streamlit 版本有明显审美提升：统一、现代、专业，有金融工作台质感。
- 每个已迁移页面都能指出旧 UI 的主要问题，并在 NiceGUI 布局中体现对应修正。
- 后端数据、策略计算和存储逻辑没有语义变化。
- 测试覆盖新 UI 的路由配置、view-model 和 app import。
- 本地浏览器截图验收通过后，再讨论是否逐步删除或降级 Streamlit UI。
