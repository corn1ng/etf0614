# 指数原子指标详情可读性改造设计

日期：2026-07-12
项目：`etf0614`

## 1. 背景与目标

`市场地图 -> 指数体检` 的指数详情已经展示了正确、可审计的原子指标，但“全部原子指标”将不同含义的值平铺成相同形态的卡片。用户必须逐项比对数值，难以快速看出价格相对均线的位置、区间位置、最近发生的事件和数据是否可靠。

本次仅改善详情弹窗的信息层级和可视表达，让用户按“位置 → 事件 → 证据”的顺序阅读。页面必须继续只陈述原子事实：不形成综合评分、趋势等级、排序、买卖建议、目标价或仓位建议。

## 2. 范围与非目标

范围：

- 调整指数详情弹窗中的“关键指标”视图，并更名为“状态概览”。
- 保留“全部原子指标”和“数据质量”视图，优化分组、异常状态和响应式布局。
- 在已有快照字段之上新增 UI 专用展示模型和 CSS，不改变指标口径或快照生命周期。

非目标：

- 不修改 `research.atomic_indicators`、指数原子快照的计算逻辑、持久化 schema 或数据维护任务。
- 不在页面打开、刷新详情或切换标签时重新计算指标、拉取外部数据或写入任何快照。
- 不将原子指标合成为“强弱”“多空”“机会”“风险”等结论性输出。

## 3. 信息架构

详情弹窗标题维持“指数原子指标：代码 名称”，右侧保留关闭按钮。标签页调整为：

1. `状态概览`
2. `全部原子指标`
3. `数据质量`

### 3.1 状态概览

状态概览开头说明“先看价格在哪里、发生过什么，再按分组核对全部原子事实”，并展示快照生成时间及当前数据可用性。正文固定为四个摘要区块：

| 区块 | 主事实 | 关键证据与视觉形式 |
| --- | --- | --- |
| 趋势结构 | 收盘相对 MA20、MA60、MA120、MA250 的实际位置 | 最新收盘价；均线阶梯图显示收盘和各均线的相对高度；上方/下方以文字标明 |
| 区间位置 | 默认 20 日收盘区间内的位置，以及是否发生新高或新低 | 区间条上的当前位置；距区间高点、低点的偏离百分比；新高、新低或区间内标签 |
| 最近事件 | 最近发生的均线穿越或区间突破事件 | 只呈现快照中已记录的最近事件和距今天数；没有事件时明确写“暂无已记录事件” |
| 数据质量 | 当前快照和历史输入是否可用于查看 | 快照状态、历史覆盖状态、有效交易日数、数据来源和最近生成时间 |

每个区块默认只显示一个主事实和一至两个数值证据。均线阶梯和区间条属于已有数值的视觉关系表达，不增加新的分析结论。桌面端四区块同行，平板端两列，窄屏端一列。

摘要区块之后显示“完整原子事实”折叠入口：默认展开“价格与均线”，其余组以标题和状态摘要呈现；用户可按需展开核对。此处用于快速追溯摘要证据，不取代完整审计视图。

### 3.2 全部原子指标

该标签页保留所有已存储原子指标，按以下可展开分组显示：

- 价格与均线
- 均线穿越
- 区间位置与突破
- 收益与回撤
- 波动与量能

每一指标行只显示“指标名 / 格式化值 / 必要状态”。正常可用的指标不再显示重复的“已计算”。只有数据不足、输入缺失、读取失败、计算失败或快照非最新时显示状态和原因。所有值、周期、样本量和数据来源仍可在该视图中审计。

### 3.3 数据质量

数据质量标签维持当前的快照生成时间、快照状态、历史状态、行数、覆盖说明、来源和错误信息。快照状态为待重建、缺失、生成中或失败时，继续使用现有的强提示文案和数据维护入口指引。

## 4. 视觉与交互规则

- 区间条以端点、当前位置和文字距离共同表达位置；不允许仅用颜色表达“高”“低”或方向。
- 均线阶梯以相对高度展示收盘和均线，始终显示 MA 周期与“上方/下方”文字标签。
- 事件时间线只记录已经发生的穿越或突破，不把持续的上方、下方状态伪装成新事件。
- 颜色不表示投资建议：蓝灰色用于中性结构与位置；绿色、黄色、红色只用于数据质量的可用、待处理、失败状态。方向状态必须有文本标签和图标，不依赖红绿。
- 任何单项缺失都显示“数据不足”及已有原因，并隐藏对应的均线阶梯、区间标记或时间线，不得用零值、空图或推测值补齐。
- “全部原子指标”中的分组可独立展开或收起；标签切换和展开操作不触发数据读取以外的计算。
- 不改变弹窗开闭、列表行点击、快照重新读取和数据维护入口的既有行为。

## 5. 数据流与代码分层

数据流固定为：

```text
本地已发布的指数原子快照
  -> load_index_atomic_snapshot_readonly
  -> UI 专用状态概览 View Model
  -> NiceGUI 指数详情弹窗
```

### 5.1 View Model

在 `src/etf_trading/nicegui_app/view_models.py` 增加独立的状态概览展示模型。它接收现有的摘要行、详情长表和快照状态，输出可测试的四个区块及折叠分组所需字段。

该展示模型只能读取已存储的 `close`、均线、相对均线偏离、区间高低标志、距区间高低偏离、穿越标志与距穿越天数、历史覆盖和快照元数据。区间条位置可由已存储的区间端点或偏离值换算为显示比例；该比例不得保存、不得反馈到领域层，也不得作为新的原子指标暴露。

当字段缺失、状态非可用或数值无法安全换算时，展示模型必须返回明确的不可视化状态，而非虚构数值或图形。

### 5.2 页面与样式

`src/etf_trading/nicegui_app/pages/market.py` 仅负责将 View Model 渲染为：状态概览的四个区块、概览内的折叠证据组、全部原子指标分组和数据质量视图。它继续使用 `load_index_atomic_snapshot_readonly`，不得导入或调用快照构建函数。

`src/etf_trading/nicegui_app/theme.py` 新增局限于 `index-atomic-*` 命名空间的布局类，复用当前工作台配色变量。新增 CSS 必须限制弹窗宽度，且在 720px 以下转为单列，以避免页面根节点横向滚动。

## 6. 异常处理

| 场景 | 行为 |
| --- | --- |
| 快照缺失、失败或生成中 | 维持现有页面级提示和数据维护指引；不渲染状态概览图形 |
| 快照待重建 | 继续展示上次成功快照，并显式标明不是最新结果 |
| 单项历史不足或输入缺失 | 仅受影响区块显示“数据不足”和原因；其他区块正常展示 |
| 没有已记录事件 | 时间线改为明确的空状态，不显示伪事件 |
| 详情中找不到所选指数 | 弹窗显示现有空状态，不尝试重建或补算 |

## 7. 验收与测试

补充或调整以下验证：

- `tests/test_nicegui_view_models.py`：正常数据、无已记录事件、单项数据不足、待重建快照下的状态概览输出；验证不产生任何结论性字段或文案。
- `tests/test_nicegui_app_import.py`：详情页面仍只读取快照，不引入构建或外部数据调用。
- `tests/test_nicegui_theme.py`：新增的指数详情布局类存在，窄屏规则把概览降为单列。
- 页面渲染测试：三标签、概览四区块、分组展开和异常状态文本稳定可见。
- 浏览器检查：在约 1440px 与 390px 宽度下，打开详情、切换标签、展开分组均无控制台错误、无根节点横向溢出；快照缺失、待重建和单项缺失场景不出现误导性图形。

所有既有指数原子计算、数据维护、主表排序与筛选回归测试必须保持通过。
