# 统一指数画像与原子指标扩展设计

日期：2026-07-30
项目：`etf0614`

## 1. 背景与目标

当前 `市场地图 -> 指数体检` 的指数详情弹窗仅包含价格、均线、区间、收益、回撤、波动和成交额等行情原子指标。现有弹窗宽度接近整屏，但内容以左侧窄列和纵向卡片呈现；均线阶梯在数值接近时还会发生标签拥挤，导致信息密度和可读性失衡。

项目已经接入 Tushare 指数行情，但 Tushare `index_dailybasic` 官方估值能力尚未落地。该接口可为受支持的核心宽基指数提供静态 PE、PE-TTM、PB、换手率、市值和股本历史。用户希望将这些估值事实、历史便宜程度、趋势、动量和风险统一到同一个指数画像弹窗中。

本设计的目标是：

- 将现有指数原子指标详情升级为统一的指数画像弹窗；
- 建立独立、可增量维护的官方指数估值历史缓存；
- 在原子快照发布时合并行情与估值，形成时间一致、可审计的统一画像；
- 使用 PE-TTM 和 PB 的近 3/5/10 年历史百分位表达便宜程度；
- 修复弹窗过宽、内容偏左、纵向堆叠和均线标签碰撞等可读性问题；
- 保持页面只读、离线和无副作用，不在弹窗交互中联网或重新计算。

## 2. 范围与非目标

### 2.1 本期范围

- Tushare `index_dailybasic` 官方估值字段接入与标准化；
- 官方估值历史的本地 Parquet 缓存；
- 首次全量与后续增量同步维护任务；
- 统一指数画像快照的估值、便宜程度、趋势、动量、风险、成交活跃度、事件和质量原子指标；
- 统一画像弹窗的五个标签：
  1. `画像总览`
  2. `估值详情`
  3. `趋势与风险`
  4. `全部指标`
  5. `数据质量`
- 独立指数估值页面继续承担多个受支持指数的横向比较，不替代统一弹窗的单指数画像。

### 2.2 非目标

- 不生成综合评分、买卖信号、目标价、仓位建议或指数排名；
- 不将不同类型指数的绝对 PE 直接比较后得出便宜或昂贵结论；
- 不通过成分股自行重建 Tushare 未覆盖指数的估值；
- 本期不计算成分股站上均线比例、新高新低家数、涨跌家数或市场宽度背离；
- 不在页面打开、刷新、筛选或切换标签时访问外部网络、构建快照或写入缓存；
- 不使用缺失值、零值或推测值补齐不可用指标。

市场宽度需要指数成分、权重及全部成分股日线，是独立的第二期能力。

## 3. 总体方案

采用“统一快照、分源缓存”方案。

```text
Tushare index_dailybasic
  -> 官方指数估值历史缓存
  ┐
指数日线历史缓存
  -> 统一指数原子画像快照构建器
  -> summary + details 已发布快照
  -> 只读 View Model
  -> NiceGUI 指数画像弹窗
```

估值历史与行情历史分别保存，便于独立维护和复用。重建指数原子快照时，构建器以行情最新交易日作为观察日，读取不晚于观察日的最近估值记录，并将两类原子事实发布到同一份 summary/details 快照。

该方案保留完整估值历史，支持未来的估值曲线和跨指数比较；同时确保弹窗只读取一份已发布的、时间关系明确的画像快照。

## 4. 数据源与覆盖边界

### 4.1 Tushare 官方估值

`TushareProvider` 增加 `index_dailybasic` 读取能力，标准化以下字段：

- `trade_date`
- `total_mv`
- `float_mv`
- `total_share`
- `float_share`
- `free_share`
- `turnover_rate`
- `turnover_rate_f`
- `pe`
- `pe_ttm`
- `pb`
- `data_source = tushare_index_dailybasic`

初始估值同步白名单与显式映射固定为：

| 内部指数代码 | Tushare 代码 |
| --- | --- |
| `000001` | `000001.SH` |
| `000016` | `000016.SH` |
| `000300` | `000300.SH` |
| `000905` | `000905.SH` |
| `399001` | `399001.SZ` |
| `399006` | `399006.SZ` |

代码映射使用显式配置，不通过指数代码前缀猜测交易所或接口代码。扩大白名单必须先用真实接口响应验证，并补充映射与回归测试。

未在白名单内的行业、主题、港股和其他指数继续生成全部可用的价格类指标，但估值组的能力状态为 `unsupported`，原因明确为“Tushare 官方估值暂不支持该指数”。

### 4.2 缓存与同步

官方估值历史使用独立的本地 Parquet 缓存：

- 首次同步下载该指数全部可获得历史；
- 后续同步从本地最后成功交易日之后增量获取；
- 重复执行必须幂等，按指数代码和交易日期去重；
- 空响应、权限失败、网络失败或字段异常不得覆盖已有成功缓存；
- 维护任务逐指数记录同步结果、实际数据日期、行数和脱敏错误；
- Tushare token 只从运行时环境读取，不进入配置、缓存、日志、任务结果或界面。

## 5. 统一快照与一致性

### 5.1 观察日对齐

统一快照以每个指数行情历史的最新有效交易日作为 `price_as_of_date`。估值取不晚于该日期的最近有效记录，并保留：

- `valuation_as_of_date`
- `valuation_lag_trading_days`
- `valuation_source`
- `valuation_support_status`
- `valuation_freshness_status`

估值日期落后行情超过 5 个交易日时，估值组标记为 `stale`。弹窗继续展示实际缓存值和两个日期，但不将旧估值伪装成当日值。

### 5.2 发布与失效

估值缓存和行情缓存都属于统一快照的输入签名。任一输入发生变化后，已有画像快照标记为“待重建”。页面不得临时拼接新估值与旧行情快照。

构建失败时保留上一份成功快照；发布继续沿用现有原子写入、校验、锁和回滚边界。

### 5.3 原子明细结构

每条指标继续使用长表明细，并至少包含：

- `index_code`
- `group_key`
- `metric_key`
- `metric_label`
- `value`
- `status`
- `reason`
- `as_of_date`
- `sample_count`
- `data_source`

百分位指标额外保存 `window_start_date` 和 `window_end_date`。摘要表只保存主表和总览需要的代表字段，不复制全部明细。

## 6. 指标体系

所有指标均为单一事实或透明变换，不合成为综合评价。

### 6.1 估值与便宜程度

- 静态 PE、PE-TTM、PB；
- PE-TTM 和 PB 的近 3/5/10 年历史百分位；
- 对应周期的历史中位数；
- 当前值相对历史中位数偏离率；
- 总市值、流通市值、自由流通市值；
- 当前换手率和自由流通换手率；
- 每项的估值日期、样本区间、有效样本数和来源。

百分位采用确定性中位秩口径：

```text
(小于当前值的样本数 + 0.5 × 等于当前值的样本数) / 有效样本数
```

PE、PE-TTM 和 PB 的非正数、无穷值与非数值记录不参与历史分位计算。每个字段独立过滤，单个字段不可用不得隐藏其他估值字段。

3/5/10 年窗口从估值观察日分别向前回溯 3/5/10 个日历年，包含起止日期。三个窗口分别要求至少 500/900/1800 个有效样本。样本不足时保留当前值和已有样本信息，但不生成百分位或分位标签。

分位标签采用固定、透明区间：

- `[0%, 20%)`：历史低位
- `[20%, 40%)`：偏低
- `[40%, 60%]`：中部
- `(60%, 80%]`：偏高
- `(80%, 100%]`：历史高位

标签仅描述当前值在自身历史中的位置，不构成交易建议。

### 6.2 趋势结构

- MA20、MA60、MA120、MA250；
- 收盘相对各均线偏离率；
- 收盘与均线、均线之间的排列关系；
- MA20、MA60、MA120 的近 20 个交易日变化率，口径为 `当前均线值 / 20 个交易日前均线值 - 1`；
- 最近上穿、下穿及距今交易日数；
- 距 20/60/120/250 日最高和最低收盘的位置；
- 20/60/120/250 日新高、新低与突破事件。

### 6.3 动量与收益

- 5/20/60/120/250 日收益率；
- RSI14；
- 近 20 日上涨交易日比例。

### 6.4 回撤与风险

- 60/120/250 日区间最大回撤；
- 当前距 60/120/250 日最高收盘的回撤；
- 20/60 日年化波动率；
- 60 日下行波动率；
- ATR14；
- ATR14 占收盘比例。

20/60 日年化波动率使用窗口内日收益率样本标准差乘以 `sqrt(252)`。60 日下行波动率使用 `min(日收益率, 0)` 的均方根乘以 `sqrt(252)`。区间最大回撤使用窗口内收盘序列相对此前累计最高收盘的最大跌幅。ATR14 复用项目现有真实波幅口径，ATR 占收盘比例为 `ATR14 / 当前收盘`。

### 6.5 成交活跃度

- 5/20/60 日平均成交额；
- 5 日与 20 日平均成交额比值；
- 当前成交额相对 20/60 日均值偏离率；
- 当前换手率及其 20/60 日均值；
- 当前换手率相对近期均值偏离率。

换手率历史只在官方估值缓存可用时计算；成交额指标仍来自指数行情历史。

### 6.6 近期事件与数据质量

- 均线穿越；
- 阶段新高、新低和突破；
- 估值分位跨越固定区间边界；
- 行情日期、估值日期、快照生成时间；
- 行情与估值来源；
- 有效交易日和有效估值样本数；
- 缺失、不支持、数据不足、过期、读取失败或计算失败原因。

事件只记录快照历史中确实发生的状态变化，不将持续状态伪装成新事件。

## 7. 界面设计

采用已确认的“画像总览 + 分域详情”方案。

### 7.1 弹窗框架

- 桌面端宽度为 `min(1180px, 92vw)`；
- 标题使用 `代码 · 指数名称`，副标题直接展示行情日期和估值日期；
- 右上角仅保留一个清晰的关闭按钮；
- 内容区域内部滚动，标题和标签保持稳定；
- 标签依次为：`画像总览`、`估值详情`、`趋势与风险`、`全部指标`、`数据质量`。

### 7.2 画像总览

第一阅读层固定为四个摘要卡：

1. PE-TTM 及 5 年历史百分位；
2. PB 及 5 年历史百分位；
3. 收盘相对 MA20 的位置与偏离率；
4. 250 日当前回撤。

若某项不可用，卡片显示明确状态和原因，不用零值或空图补位。

第二阅读层包含：

- 估值历史位置：PE-TTM、PB 分位轨道，补充 3 年和 10 年分位；
- 趋势结构：使用稳定的关系行和相对条，不再使用容易碰撞的竖向均线阶梯；
- 动量与风险：用紧凑指标胶囊展示代表项；
- 近期事件：按时间从近到远展示；
- 数据可用性：展示估值和价格指标可用数、实际来源与日期。

颜色只用于区分结构、交互和数据质量。估值高低、价格方向和收益正负必须同时有文字与数值，不能只靠红绿表达。

### 7.3 分域详情

`估值详情` 展示当前估值、3/5/10 年分位、中位数、偏离率、样本区间和样本数。

`趋势与风险` 按趋势结构、动量收益、回撤波动、成交活跃度分区，以两列或三列紧凑网格展示。

`全部指标` 保留所有已发布原子事实，使用分组折叠和多列网格，不再将每项渲染成占满一行的大卡片。每行只呈现指标名、格式化值和必要状态；来源、观察日和样本数可在组内辅助信息中核对。

`数据质量` 集中展示快照状态、输入签名状态、行情覆盖、估值覆盖、实际日期、来源、行数和错误原因。

### 7.4 响应式行为

- 宽屏：摘要四列，主要内容两列，次级摘要三列；
- 中等宽度：摘要与主要内容两列；
- 720px 以下：全部降为单列，标签允许横向滚动；
- 任何断点都不得产生页面根节点横向溢出；
- 数值与标签不得因数值接近而发生视觉碰撞。

所有新增样式限制在 `index-profile-*` 命名空间，避免影响其他工作台和表格。

## 8. 异常状态

| 场景 | 行为 |
| --- | --- |
| Tushare 官方不支持 | 估值区域显示能力不支持，不绘制百分位轨道；其他指标照常显示 |
| 尚无估值缓存 | 显示“尚无本地估值缓存”，引导到数据维护任务；页面不联网 |
| 估值落后超过 5 个交易日 | 展示旧值、实际日期和“估值数据已过期”状态 |
| 百分位样本不足 | 展示当前值与样本信息，不生成百分位和分位标签 |
| 单个估值字段非法或缺失 | 仅该指标不可用，其他估值字段独立展示 |
| 同步失败 | 保留旧缓存，维护任务记录脱敏失败原因 |
| 快照输入发生变化 | 旧快照标记待重建，不在页面拼接新旧输入 |
| 快照构建失败 | 保留上一份成功快照和失败状态，不发布半成品 |
| 选中指数没有快照明细 | 弹窗显示明确空状态，不现场构建 |

## 9. 代码边界

- `data/providers/tushare_provider.py`：只负责调用和标准化官方估值接口；
- 指数估值数据模块：负责标准 schema、代码白名单和缓存契约；
- 指数估值同步服务：负责首次、增量、幂等和失败保留；
- `research/index_health_snapshot.py`：负责读取本地行情与估值历史并生成统一原子快照；
- `nicegui_app/view_models.py`：负责把已发布原子事实转换为五个标签所需的只读显示模型；
- `nicegui_app/pages/market.py`：只负责渲染，不导入 provider、同步服务或快照构建函数；
- `nicegui_app/theme.py`：只包含本弹窗专用样式；
- 数据维护页面与任务运行器：负责显式同步和重建入口、进度及持久化结果。

## 10. 验收与测试

### 10.1 数据与同步

- Tushare 字段标准化、日期和数值转换；
- 受支持代码显式白名单及未支持代码；
- 首次全量、增量边界、重复执行和去重；
- 空响应、权限失败、网络失败和 schema 异常保留旧缓存；
- token 与错误信息脱敏。

### 10.2 指标计算

- 3/5/10 年窗口边界；
- 百分位中位秩口径、相同值、缺失值、非正数和无穷值；
- 最低样本量与明确不足原因；
- 估值日期对齐、5 个交易日过期边界；
- 新增趋势、动量、风险和成交活跃度指标的确定性小样本测试；
- 未支持指数仍完整生成价格类指标；
- 输入变化使旧快照进入待重建状态；
- 构建或发布失败保留上一份成功快照。

### 10.3 View Model 与页面

- 五个标签及其分组；
- 正常、未支持、未同步、过期、样本不足和部分字段缺失状态；
- 页面只读取统一快照，不导入或调用外部 provider、同步服务和构建函数；
- 全部指标使用紧凑多列布局；
- 不出现综合分、买卖信号、目标价、仓位或推荐文案。

### 10.4 视觉验证

在 1440px 和 390px 浏览器视口宽度下验证：

- 弹窗宽度与内部滚动正常；
- 摘要卡、估值分位轨道和趋势关系行可读；
- 标签切换、折叠组和关闭按钮工作正常；
- 无均线标签碰撞；
- 无根节点横向溢出；
- 缺失、不支持、过期和样本不足状态不产生误导图形；
- 浏览器控制台无错误或警告。

完成聚焦测试后运行完整 `pytest`。

## 11. 与既有设计的关系

本设计继承 `2026-07-19-official-index-valuation-design.md` 中的官方数据源、独立缓存、显式维护任务、页面不联网和不重建成分股估值等边界。

本设计更新其呈现范围：官方估值不仅用于独立横向比较页，也进入统一指数画像快照和单指数详情弹窗。任何实现计划以本设计的统一快照和五标签弹窗为准。
